# VoxCanvas Demo 脚本

日期：2026-06-14

## 1. Demo 目标

这段 Demo 用于展示 VoxCanvas 的核心价值：用户通过语音完成绘图、编辑、撤销重做、复杂组合绘制，并在需要复杂视觉表达时进入受管理的 AI 生图和语音改图路径。

建议视频时长控制在 5 到 7 分钟。正式录制时以真实语音输入为主；页面中的 `Development only` 模拟输入框只作为开发调试入口，不作为正式演示主路径。

## 2. 录制前检查

录制前先完成以下检查：

1. 使用支持 `SpeechRecognition` / `webkitSpeechRecognition` 的浏览器，推荐 Chrome。
2. 确认浏览器已允许麦克风权限，语音识别语言为 `zh-CN`。
3. 本地运行 `pnpm dev`，打开 Vite dev server 页面。
4. 如果演示 LLM 容错，确认 `.env` 已配置 `VOXCANVAS_LLM_PROVIDER`、对应 API key 和可用语义模型。
5. 如果演示 AI 生图和语音改图，确认 `.env` 已配置 `DASHSCOPE_API_KEY`、`VOXCANVAS_IMAGE_MODEL=wan2.7-image-pro` 和合适的 `VOXCANVAS_IMAGE_SIZE`。
6. 修改 `.env` 后重启 dev server。
7. 录制前刷新页面，确保画布为空，Command trace 没有旧失败信息。
8. 准备一份备用说明：如果网络或模型服务临时失败，展示系统的 pending / failed 状态和脱敏错误反馈，说明结构化绘图主链路不依赖生图服务。

## 3. 主录制脚本

### 3.1 开场介绍

画面：打开 VoxCanvas 首页，展示顶部品牌、中央大画布、左侧语音控制面板和右侧 Command trace。

旁白：

```text
大家好，这是 VoxCanvas，一个面向无障碍创作和快速草图表达的纯语音 AI 绘图工具。
这个项目对应企业实训营选题二：AI 语音绘图工具。
它的核心目标不是用鼠标画图，而是让用户通过语音完成图形创建、对象编辑、撤销重做、复杂组合绘制，以及后续的 AI 生图和语音改图。
```

继续旁白：

```text
界面中间是主画布，左右两侧是浮动工作面板。
左侧负责语音输入和麦克风状态，右侧会展示识别文本、解析意图、操作预览和执行反馈。
这样评委可以看到系统不是直接改 DOM，而是把语音转成结构化操作，再进入画布状态和历史管理。
```

### 3.2 麦克风启动与基础绘图

画面操作：点击 `Start voice`，如果浏览器请求权限，允许麦克风。

旁白：

```text
我先启动语音识别。接下来所有画布操作都通过语音发出。
```

语音指令：

```text
画一个蓝色圆形
```

预期结果：

- 画布中出现蓝色圆形。
- Command trace 显示 recognized text、parsed intent、operation preview 和反馈日志。

旁白：

```text
这是最基础的语音到图形闭环。系统识别到中文语音后，先走本地规则解析，生成 create_shape 操作，再由操作队列更新画布状态。
```

语音指令：

```text
在左上角画一个红色矩形
```

预期结果：

- 左上区域出现红色矩形。
- 右侧操作预览显示矩形、颜色和位置。

旁白：

```text
这里展示了颜色和位置控制。简单、确定性的指令不需要调用大模型，所以延迟更低，也更稳定。
```

### 3.3 对象编辑与连续语音输入

语音指令：

```text
把刚才的圆变大
```

预期结果：

- 最近的圆形变大。
- Command trace 显示 update_shape / resize 类操作预览。

语音指令：

```text
往上一
```

预期结果：

- 最近对象向上移动。
- 输入框在上一条指令执行后已自动清空，不会把两条语音粘连成一条。

旁白：

```text
这里展示的是对象引用和连续语音处理。系统会优先找到选中对象、最近对象，或者最近匹配类型的对象。
同时，每条 final transcript 执行后会自动开启新输入，避免连续说话时出现“画一个圆画一个正方形”这种粘连问题。
```

语音指令：

```text
删除正方形
```

预期结果：

- 最近的矩形被删除。
- 系统不会把“删除正方形”误判成“画一个正方形”。

旁白：

```text
删除指令会优先按照显式编辑处理，而不是重新创建图形。
所有删除、移动、变色和缩放仍然会进入统一 DrawingOperation，所以可以被历史系统管理。
```

### 3.4 撤销、重做与清空

语音指令：

```text
撤销
```

预期结果：

- 被删除的矩形恢复。

语音指令：

```text
重做
```

预期结果：

- 矩形再次被删除。

旁白：

```text
撤销和重做由 HistoryManager 管理完整画布快照。
这意味着结构化图形和 AI 图片图层都可以通过同一套历史机制恢复。
```

语音指令：

```text
重新来
```

预期结果：

- 画布被清空。
- Command trace 显示清空画布操作。

旁白：

```text
“重新来”“回到最初状态”“全部清掉”这类自然表达已经被归一为清空画布。
这类高频演示表达优先由本地规则覆盖，避免每次都依赖网络模型。
```

### 3.5 数量指令与复杂结构化组合

语音指令：

```text
画两个圆
```

预期结果：

- 画布中出现两个圆形。
- operation preview 显示 count。

旁白：

```text
数量指令会展开成多个 create_shape 操作，而不是只创建一个图形。
```

语音指令：

```text
重新来
```

预期结果：

- 清空画布，准备展示复杂组合。

语音指令：

```text
画一座房子，有红色屋顶、黄色墙体、两个窗户和一扇门
```

预期结果：

- 画布中出现房子草图：墙体、屋顶、窗户和门。
- Command trace 显示模板展开后的多个操作。

旁白：

```text
这一步展示复杂组合指令拆解。
VoxCanvas 没有让模型直接生成不可解释的图，而是通过模板展开器，把“房子”拆成墙体、屋顶、窗户和门等多个合法图形操作。
这些图形仍然可以被选择、移动、删除、撤销和重做。
```

### 3.6 AI 生图与语音改图

画面操作：如果上一段房子仍在画布上，可以先说“重新来”，保持 AI 图片区域更清楚。

语音指令：

```text
画一只蓝色的鸟
```

预期结果：

- 画布中先出现图片图层加载动画。
- 图片生成成功后，图层回填真实图片。
- 如果失败，图层显示失败状态和脱敏错误信息。

旁白：

```text
对于鸟、人物、风景、风格化场景这类结构化图形不擅长的内容，系统会进入 AI 生图路线。
它仍然不是直接把图片丢到页面上，而是先创建受管理的 pending 图片图层，进入历史记录，然后通过本地代理调用图片模型，成功后再回填 imageUrl。
API key 只保存在本地环境变量和 Vite 代理中，不会进入前端代码。
```

等待图片成功后，继续语音指令：

```text
把这只鸟换成黑色
```

预期结果：

- 系统基于上一张成功图片和新指令创建新的图片图层。
- 新图生成成功后显示黑色鸟或更接近黑色鸟的结果。

旁白：

```text
这是语音改图能力：旧图加新语音指令生成新图。
当前版本不引入鼠标框选、橡皮或手动 mask，而是保持纯语音路径。
旧图仍然保留在历史里，用户可以继续撤销或重新描述修改目标。
```

### 3.7 语义容错可选片段

如果 LLM provider 在录制环境稳定，可以加入这一段。若网络或模型服务不稳定，可以跳过，不影响主链路展示。

语音指令：

```text
画一个园
```

预期结果：

- 如果语义模型可用，系统将同音错字“园”归一为“圆形”，并创建圆形。
- 如果语义模型不可用，Command trace 会展示安全失败状态，画布不被错误修改。

旁白：

```text
这里展示语义容错。规则解析器不强行猜测所有同音错字，规则无法覆盖时会进入 LLM Semantic Planner。
模型输出也不能直接修改画布，必须先转成结构化计划，再经过 OperationValidator 校验。
如果模型服务不可用，系统会保留失败诊断并保持画布安全。
```

### 3.8 收尾总结

画面：展示最终画布和 Command trace。

旁白：

```text
总结一下，VoxCanvas 的核心实现分成三层。
第一层是稳定的结构化绘图：语音识别、本地规则解析、DrawingOperation、OperationQueue、CanvasState 和 HistoryManager。
第二层是语义规划：当语音里有同音错字、自然表达或复杂任务时，由 LLM 负责理解意图，但它只能输出结构化计划。
第三层是 AI 图片图层：复杂视觉对象走受管理的图片图层，支持 pending、succeeded、failed 状态，也接入撤销和重做。
```

继续旁白：

```text
这个项目的重点是稳定、可解释、可持续提交的纯语音绘图闭环。
简单图形保持低延迟，复杂语义和复杂视觉表达交给 AI，但所有结果都会经过 schema、validator 和历史管理约束。
以上就是 VoxCanvas 的 Demo，谢谢观看。
```

## 4. 备用录制路线

如果图片生成服务在录制当天不稳定，可以使用以下路线保证主 Demo 完整：

1. 完整展示基础图形、对象编辑、撤销重做、数量指令和房子模板。
2. 对 AI 生图只展示 pending 到 failed 的安全状态，并说明失败原因已脱敏，API key 未暴露到前端。
3. 口头说明真实图片生成和语音改图由 `/api/image-generation` 本地代理接入，相关单元测试和请求体构造已经覆盖。

如果浏览器语音识别不稳定，可以先重启浏览器页面并重新授权麦克风。正式视频仍应优先录制真实语音输入；开发模拟输入框只用于排查问题。
